# 游戏概念与界面元素词典

用途：让下一位 AI、动画制作同伴和开发者先对齐“每个东西究竟代表什么”，再接动画。本文定义来自用户最终要求及已确认源码，不新增玩法。与 [最新交接说明](NEXT_AI_HANDOFF.zh-CN.md)、[分支文档地图](BRANCH_DOCUMENT_MAP.zh-CN.md) 配套。

## 1. 游戏在讨论什么

玩家扮演教师，为课堂设定评价规则。学生适应这些规则，报表可能改善，但这不自动证明理解、思考或真实交流改善。

三关分别检查三种直觉：

| 关卡 | 玩家尝试 | 游戏实际能展示的证据 | 不应擅自得出的结论 |
| --- | --- | --- | --- |
| Level 1 | 选择一个指标作为评价依据 | 符合该标准的学生比例上升；观察到部分学生应付标准 | 高比例＝真实学习改善；或所有学生都在作弊 |
| Level 2 | 增加指标、补齐遗漏 | 覆盖变多，学生越来越围绕清单安排工作 | 指标越多越好；或任何多指标评价都无效 |
| Level 3 | 改变三个指标的评分权重 | 真实权重对应的相对投入与停止行为 | 找到一组完美权重就能量化／保证学习改善 |
| Design Lab | 写反思、匿名反应和排名 | 一份作品获得多少鲜花，以及排名意识是否影响表达 | 鲜花最多就客观代表思考最好 |

标题副句 **Do better numbers mean better learning?** 是开放问题，不是“所有测量都没有用”。游戏没有独立测量真实学习成效，也没有隐含的“学习健康值”。

## 2. 最容易混淆的四类数字

| 数字 | 单位／范围 | 主体／分母 | 具体含义 |
| --- | --- | --- | --- |
| Level 1 Evaluate 的 34% → 88% 等 | 学生比例，0–100% | 班级学生中，符合当前选定标准者 | 两次 assessment 的标准达成比例；是预设示例值 |
| Level 2 的 3、6、10、25、100 | 项目个数 | 评价系统中的指标／要求 | 清单覆盖与膨胀的规模，不是学生成绩 |
| Level 3 的 45%、45%、10% 等 | 评分权重，总计 100% | 当前选定三个指标的评分份额 | 哪些项目对得分更重要，不是分配时间或学习收益 |
| 管理层绿色条内部 44、60、90 等 | 叙事条位置，内部 0–100 | 无统计分母 | 管理层对报表的满意程度展示，不是一个实测百分比 |

此外 Lab 的鲜花是**有效同意票的个数**，10 秒／90 秒／210 秒是计时。它们都不能与上述任何百分比直接比较。

## 3. Evaluate 的数字：精确定义

### 3.1 玩家看见的数到底是什么

最终可见标签：**Percentage of students meeting the criteria**。

概念公式：

**符合当前选定评价标准的学生人数 ÷ 此次被评价的班级学生人数 × 100%。**

公式解释这个比例的含义；当前游戏并不创建真实学生名单再计算，而是读取固定的示例数据。课堂参与本游戏的人数最多 21，与故事里被评价班级的示例百分比没有换算关系。不能据此猜“88% 一定等于现场多少名同学”。

- **First assessment**：故事中的第一次评价，对照基线。
- **Second assessment**：故事中的第二次评价，学生知道当前指标会影响得分并适应标准后的结果。
- before／after 是上述两次评价的程序字段，不是动画播放前后、玩家点按钮前后或两个不同班级。
- Evaluate 是查看／呈现这套示例评价结果，不是让系统用玩家预测文本打分。
- 标准保持同一口径才有可比性。不要把前值说成理解力、后值说成任务完成率。
- 这是故事中的设定对比，不证明真实教学中的因果关系或政策效果。

例如课前准备 **34% → 88%**：第一次有 34% 的班级学生符合准备清单标准，第二次是 88%；增加 **54 个百分点**。不表示 Alex 从 34 分学到 88 分，不表示理解提高 54%，也不是“88% 的知识掌握”。

### 3.2 六项标准与固定结果

权威数据位置：`src/levels/level1/metrics.ts`。共用名称目录 `src/shared/data/metrics.ts` 不包含 assessmentCriteria 或该关 before／after。

| ID／指标 | 达标标准（实际英文） | First → Second | Observe 的学生行为摘要 |
| --- | --- | --- | --- |
| prep / Pre-class Preparation | Complete the preparation checklist. | 34% → 88% | Skimming just to finish. |
| part / In-class Participation | Make at least one contribution in class. | 29% → 85% | More talk. Little explanation. |
| focus / On-task Focus | Be recorded as on task during classroom checks. | 41% → 91% | Looking busy takes priority. |
| discuss / In-class Discussion Quality | Ask a follow-up question and build on a classmate’s point. | 32% → 84% | Discussion turns formulaic. |
| reflect / Learning Reflection Quality | Use the reflection format: describe your thinking before and after. | 38% → 89% | Repeating safe reflection patterns. |
| peer / Online Peer Response Quality | Include a specific suggestion and a follow-up question in your response. | 27% → 86% | Replying to tick boxes. |

**Quality 出现在指标名称里，也不意味着程序已经客观测得真实质量。** 本关将抽象质量操作化为可被检查的行为／格式；学生满足形式要求与真实思考之间的落差，正是观察环节的重点。

### 3.3 这个数字怎样与 Observe 配合

以 Focus 为例：

1. 教师希望了解学生是否在思考。
2. 实际采用“课堂检查时被记录为 on task”这个标准。
3. 第二次达标比例达到 91%，报表改善。
4. 观察 Alex 时发现他重视“看起来忙碌”。
5. 两种信息并不冲突：可见标准达成，深度思考却仍不明确。

报表是班级层面的标准达成信息；Alex 是具体叙事个案，用来展示适应规则的方式。不要把 Alex 一个人的行动说成百分比计算的全部数据，也不要凭一个片段断言全班每个人都相同。

## 4. 指标、标准、目标、得分：四个不同概念

| 术语 | 本项目定义 | 合并时的边界 |
| --- | --- | --- |
| Metric / 指标 | 选择观察和评价的一个方面，例如准备、专注、反思 | 六项身份用稳定 ID 传递，不能按画面位置猜 |
| Criteria / 评价标准 | 为某指标设置的具体可检查要求，例如至少发言一次 | 达到标准不是证明达到全部教育目的 |
| Marks / 学生得分 | 满足评分要求后获得的分数／学分奖励，是角色行动动机 | 当前没有展示每个学生完整成绩账本，不能发明精确个人总分 |
| Target / 旧目标线 | 老版本用于报表的目标阈值，历史可见值为 70 | 最新 Level 1 结果页已去掉，不恢复刻度或 target-met 文案 |
| Learning / 学习目的 | 理解、形成想法、真实交流等希望促进的事情 | 当前没有独立学习测量值，不能和报表得分画等号 |

**“结果页去掉 target”不等于“criteria 也去掉”。** 标准是比例口径和故事动机的基础，应保留。程序里的 legacy `target`／`targetMet` 字段仍可能为兼容存在；不能因为搜到字段就把旧目标展示恢复。

## 5. 界面阶段与不同层次的结果

| 元素 | 是什么 | 不是／不要误用成 |
| --- | --- | --- |
| Choose | 玩家选采用哪个指标；后续关选择三项 | 系统推荐正确答案 |
| Predict | 玩家写下预期，记录自己的假设 | 自动批改文本、按关键词评分 |
| Evaluate | 呈现所选标准的评价数据／报表 | 证明学习发生的裁判 |
| Observe | 看课堂后果，核对报表之外的行为 | 另加 Results 导航阶段 |
| Classroom cinematic | 对真实选择的故事呈现 | 第二套独立算分或 effort 规则 |
| Settlement / 关卡结算 | 动画后将管理层反应与学生状态并列回顾 | 再播放同一套师生对话或把全部动画叙述抄一遍 |
| Placeholder | 明确标示尚未交付的动画槽位 | 最终影片、已通过的动画替代品 |

**Evaluate 数字条上升**与**Level 1 结算管理卡静态**是两个位置的要求，不相互抵消。不要把“进度条去掉”误删所有条：用户删的是电影播放器时间／播放进度 UI，评价数据条和管理层反馈条仍有用途。

## 6. Management’s view：管理层满意，不是学习指标

管理层看到报表符合要求、指标更丰富、权重正式发布而满意。它与学生风险可以同时出现，这是有意设计的两种视角。

当前实现 `src/shared/components/ManagementSatisfaction.tsx`：

| 完成的报告事件 | 内部条位置 | 可见定性状态 |
| --- | --- | --- |
| 尚未出报告 | 12 | Awaiting results |
| Level 1 报表完成 | 44 | Satisfied |
| Level 2：3 项 | 60 | Satisfied |
| Level 2：6 项 | 70 | Very satisfied |
| Level 2：10 项 | 77 | Very satisfied |
| Level 2：25 项 | 82 | Very satisfied |
| Level 2：100 项 | 86 | Very satisfied |
| Level 3：发布第 1 次权重 | 90 | Very satisfied |
| Level 3：发布第 2 次权重 | 93 | Delighted |
| Level 3：可选第 3 次权重 | 95 | Delighted |

这些数只供动画／状态对齐，不向玩家额外印成“满意率 90%”。第三次是实际玩家可选试验，不是旧文档说的系统 reference publication。

- Level 2 从上一关 44 开始，结束 86；Level 3 从 86 开始。独立预览也用对应关卡基线，不代表玩家偷偷玩过前面关卡。
- 只在报告／发布完成后推进；拖滑条、确认、重播、打开比较不增加满意度。
- 第三关不同配比没有额外奖励；平均权重不比偏重权重获得更高满意度。
- Level 1 最新结算不重播条上升、不显示管理卡底部说明；不把这条要求扩成删除 Level 2／3 的报告上下文。
- 管理层绿色意为报表得到认可，不是“这是正确教学方案”。

## 7. Students、Learning at risk 与等待状态

- **Students**：学生行为的概括，是定性观察，不是一个分数。
- **Awaiting observation**：本轮还没有完成课堂观察。不能把上一轮的行为或结局提前当成本轮已知结果。
- **Learning at risk**：提示评分行为可能遮蔽学习目的。它不是测得学习下降、不是学生受伤／健康值，也不是失败判定。
- “Understanding still unclear”等表述的 **unclear** 是证据不足；不能擅自改为“已证实没有理解”。
- 负面学生边框强调是引导注意，不是额外扣分机制。没有隐藏 HP、胜负分或负向百分比。

Level 2 当前阶段摘要在 `src/levels/level2/data.ts`：

| 数量 | Students 文案 |
| --- | --- |
| 3 | Untracked areas get overlooked. |
| 6 | Meeting criteria becomes the goal. |
| 10 | Ticking boxes takes priority. |
| 25 | Optimizing for the criteria takes priority. |
| 100 | Doing the minimum becomes the strategy. |

Level 3 当前一次观察：有 Minimum → **Low-weight areas get less attention.**；没有 Minimum → **Stops when the criteria are met.**；比较页总结 → **Scores still set the stopping point.** 不要将它们混成任何关卡通用的唯一状态句。

## 8. Checklist 与打勾：必须看所处阶段

| 出现位置 | 勾／数量表示什么 |
| --- | --- |
| Level 2 选择页 Alex’s Checklist | 已选入评价的指标，计数 N / 3 selected；不是学生已经完成 |
| Level 2 评价／课堂清单 | 对当前评价标准的覆盖或角色满足要求的表现，依对应场景决定；不是学会知识 |
| Level 2 的 10／25／100 | 要求数量膨胀。前六项有明确身份，其后不是要另外创造 94 个教育指标 |
| Level 3 权重发布勾 | 评分规则已确认／发布，不表示任务做完 |
| Level 3 停止序列的勾 | Alex 在其优先任务上完成所需评分要求；低投入项不能也全勾 |
| 开头三个学生的完成标记 | 玩家已看过三个个案的进度，与成绩无关 |

Notebook／纸张图形是将指标与清单行为具象化的视觉元素。Level 1 Students 小插图不是新剧情、可点击控件或需要另测的第七个 metric。

## 9. Level 3：权重、effort、覆盖与停止动机

### 9.1 权重 Weight

三个已选指标对评分的重要份额，正整数、总计 100，每项至少 1。**不是** Alex 的时间百分比、实际精力消耗百分比、班级达标比例或学习收获。

初始滑条在 0、卡片显示 —，表示 **unassigned**，不表示三个已生效的零权重。这个未分配状态不能送进 effort 计算或存成真实试验。

确认按钮锁定当前评分份额；不是选择系统认定的正确配比。剩余联动确认维持合计 100。

### 9.2 Effort / 投入档位

Minimum、Steady、Intense 是相对奖励结构下的**定性行为类别**。条形一格／两格／三格只是对应档位，不是 33%／67%／100% 实测努力。

算法比较某项权重与其他两项，差距 ≤10 算相近；更高比较更多是 Intense，更低更多是 Minimum，打平是 Steady。完整例子和边界见最新交接第 6 节及 `weights.ts`。这里不维护第二份算法。

- Intense 不等于最好；可能抢答、刻意维持忙碌、逐条追分。
- Steady 表示任务得到正常投入，不自动表示内在动机、深入学习或最终成功。
- Minimum 表示相对忽视，不自动表示零投入、所有要求都未完成或学习绝对下降。
- Near-even 定义为最大与最小权重差 ≤10；是描述配比的词，不是强制玩家必须找到的解。

### 9.3 Attention / Coverage 与 Stopping point

**注意／投入分布**回答“更重视哪项”；**停止点／动机**回答“为什么继续、何时结束”。调整可以改善前者，但学生仍可能按评分要求决定后者。

三项 Steady 的镜头必须既有投入，又有满足标准后收起材料；不能只演认真工作，把未解决的问题藏掉。含 Minimum 的镜头不能假装全部标准已完成。对白和 Hint 都应区分这两条线。

### 9.4 Trial / Run / Comparison

- 一次真实试验包含同轮指标身份、权重、已观察 effort。只编辑未观察／取消可选第三次，不产生新结果列。
- 第二次完成后即可继续；第三次可选。没有系统补出来的平均对照组。
- **Same effort**：同一 metric 与上一真实试验的档位相同，即使百分比变了。
- **More / Less effort**：定性档位升／降，不是按权重数值大小直接贴标签，更不是学习增／减。
- `compared` 里 nearEven／uneven 可以为空；它为空并非玩家没完成。真实 `runs` 才是完整证据。
- 主问题＋Hint＋Students view 都基于同一真实观察；Hint 是可选启发，不是必须达成的关卡任务或正确答案指示。

## 10. 角色、视角与姓名

玩家是教师，开头输入的名字替换老师的显示名称和邮件称呼；Maya 可能仍是旧源码角色键，不应漏到最终用户界面。Alex 是学生个案，不替换为玩家姓名。

Teacher 的第一人称用 **I**；Level 1 只选一个指标，因此 **The number** 是单数。不要为统一字符串把所有关卡、所有句子的 numbers 全改成单数。

电影老师金色、学生浅蓝色用于分辨发言人，不表示对错或获奖。操作界面原有头像／对话气泡系统与电影字幕是不同呈现层，不应强制同一种排版。

## 11. Design Lab 的概念边界

| 元素 | 定义 |
| --- | --- |
| Participant | 最多 21 位课堂参与者；老师也可参与。主持页不是额外作品作者 |
| Reflection | 一份简短观点／反思；不是考试，不自动批改，不继承玩家游戏预测 |
| Anonymous | 展示用 Reflection 编号，不公开姓名；内部不透明 ID 用于路由与单次投票，不是用户账号 |
| Flower / Agree | 一张同意票；最后计入排序 |
| Bomb / Disagree | 一张不同意票，不从鲜花数扣分 |
| No vote | 超时未选，既非同意也非不同意，不能归入炸弹 |
| Ranking | 仅按鲜花个数的只读排序，不是思考质量评估；并列相邻、同名次 |
| Next | 提前看下一份；自己作品可跳过、不自投；未投其他作品需等该份超时 |
| Waiting | 个人已结束，在等全体完成或总窗口截止，并非游戏卡死 |
| Classroom / Session | 老师本机进程里的当次课堂活动；没有必要的房间码或云账号流程 |
| Local version | 老师电脑提供网页服务，同学用局域网地址访问；不要求每位学生运行服务器 |

21 份 × 10 秒＝210 秒是展示最长窗口，不是写作加展示的总时间；写作另有固定 90 秒。看自己作品也占一份展示，不能自行改成 20×10。

事先宣布匿名展示与排名，但不提前解释只按鲜花算名次。两问检验玩家对这个指标和自己表达策略的反思；不把“鲜花最多的必然差”当成标准答案。

最终半身像是插画，Goodhart 原话与游戏里流行表述需区分。界面结束保留思考空间，不新增一轮必填反思。

## 12. 资源和工程术语，避免误读

- **Scene request**：游戏给动画的真实上下文，含 ID、姓名、指标、权重／effort／历史。动画按它选片，不反向伪造选择。
- **Complete callback**：动画真正结束后通知宿主继续，不是播放器每次重绘都触发；同一次结束应只推进一次。
- **Standalone preview**：某一关可独立试玩，可能使用默认姓名／入口基线；不意味着完整游戏不需要姓名传递。
- **Backup / archive**：保存以前的真实状态，供回退和比对；不是另一个必须同步更新的当前产品。
- **Validation report**：在特定构建上执行检查的记录，不等于所有平台都测过，也不等于证明教育效果。
- **ZIP / self-contained HTML / Windows EXE**：不同交付容器。游戏目前离线 HTML；Lab 是本地服务器 EXE。未来合并需统一启动／路由，但不能因此改变课堂规则。
- **No saving**：游戏误退出不恢复；Lab 当次匿名作品和票须暂存在老师进程才能多人互动，这不违反“不保存游戏记录”。

## 13. 合并前请用这几个例子自检是否对齐

1. **88**：应答“第二次评价中 88% 学生符合 prep 标准”，不能答“Alex 得 88 分”。
2. **45/45/10**：应答“评分权重，触发高／高／低相对投入”，不能答“学习时间分配”。
3. **95** 管理条：应答“第三次实际发布后的叙事满意位置”，不能答“学习质量 95%”。
4. **100** 第二关：应答“评价要求扩张到 100 项”，不能答“所有学生满分”。
5. 全部 Steady：可以承认注意更均衡，仍须观察达标就停；不判定完美通关。
